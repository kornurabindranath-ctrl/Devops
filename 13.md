# Phase 2 Terraform Backend

By default, Terraform stores its state in a local file:

terraform.tfstate

This has several problems:

If your laptop crashes, you lose the state.
Team members cannot collaborate.
CI/CD pipelines cannot use the same state.
There's no state locking, so two people can run terraform apply simultaneously and corrupt the state.

A production setup stores the state remotely.

Configuring  Terraform so it stores its state in the S3 bucket .

bash
```
terraform {
  required_version = ">= 1.6.0"

  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
}
```
This file tells Terraform:

Use Terraform version 1.6 or newer
Use the AWS provider
Use provider version 5.x

bash
```
provider "aws" {
  region = var.aws_region

  default_tags {
    tags = {
      Project     = "Usecase-13-ArgoCD-MultiCluster"
      Environment = "Management"
      ManagedBy   = "Terraform"
      Owner       = "Rabindranath"
    }
  }
}
```
Every AWS resource Terraform creates will automatically receive these tags.

for every VPC, subnet, EKS cluster, IAM role, and security group, Terraform applies them automatically.

bash
```
terraform {

  }
}
```

Creating a public subnets for vpc by addding in vpc module

bash
```
resource "aws_subnet" "public" {
  count = length(var.public_subnets)

  vpc_id                  = aws_vpc.this.id
  cidr_block              = var.public_subnets[count.index]
  availability_zone       = var.availability_zones[count.index]
  map_public_ip_on_launch = true

  tags = merge(
    local.common_tags,
    {
      Name = "${var.project_name}-${var.environment}-public-${count.index + 1}"

      "kubernetes.io/role/elb" = "1"
    }
  )
}
```
